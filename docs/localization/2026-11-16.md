## Architecture and access decision

Next.js App Router; existing components accept explicit en/ru locale props. No next-intl/i18next or global translated route tree exists. Public English routes use no prefix; existing Russian routes use /ru (Trips/course), articles have actual counterpart slugs, Media has a local language selector.

Confirmed languages: English and Russian. No evidence for adding Dutch or Hebrew; RTL is therefore out of scope for this release. Fonts and design belong to this site: Inter/Newsreader, existing ink/blue/copper palette.

Jewish portfolio uses /private/jewish and /private/jewish?lang=ru. Both remain inside the existing /private security-header scope. No translation JSON, private static export, private sitemap entry or private hreflang is introduced. Copy stays in a server route. The language switch uses document navigation: Next layouts persist during client navigation and otherwise leave the chrome in the previous query locale.

Alex explicitly requested open human access without a code on 16 November. Production already used direct-link access; the new route removes its fake-session/gate branch. All private routes stay noindex/nofollow/noarchive/nosnippet/noimageindex; robots.txt excludes the landing path and descendants. These are crawler directives, not authentication. Ordinary browser selection, clipboard copying/cutting, dragging and context menu are deterred; screenshots and source extraction are not technically preventable.

The nonmodal notice appears on a new mount of the Private layout, dismisses with its acknowledgement button and remains dismissed while navigating within the mounted area. Removed sessionStorage suppression so a historic dismissal does not permanently hide a new visit's notice.
